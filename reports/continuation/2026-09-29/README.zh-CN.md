## 失败观察

- **Claude Code**：阶段 3 后的摘要触及 2,048-token 输出上限，未提交第三次压缩。
- **Qwen Code**：阶段 1 后的摘要与恢复内容会使历史 token 增多，压缩被拒绝。
- **ZCode**：阶段 1 后的摘要与恢复内容未小于选中的历史，压缩被拒绝。
- **Kimi Code**：阶段 1 后的摘要与恢复内容未小于选中的历史，压缩被拒绝。

具体压缩失败事件见 [compaction-errors.json](compaction-errors.json)。摘要成功本身不代表能继续完成任务。每组仅一次随机生成，无法据此给策略排名或将代码缺陷归因于压缩。

以上失败均保留原上下文。本轮在较短历史上强制压缩，结果反映了该任务与预算下的行为，不能用来评价插件默认的自动压缩策略。

## 早先的观测

首次部分覆盖的结果原样保存在 [initial-results.json](initial-results.json) 和 [initial-final-sources.json](initial-final-sources.json)：基线 24/24，Cline 22/24。失败项为 `retry-schedule` 和 `attempt-limit`：导入实现向接收“刚完成的请求次数”的辅助函数传入了下一次请求次数，导致第二次请求前等待 500ms，并在第三次请求前停止。这条观测与本次完整运行一并保留。两轮覆盖范围不同，不合并为各策略等量的重复实验。

最初联网尝试在获得模型响应前失败，两次 `fetch failed` 记录保存在 [connection-attempt.json](connection-attempt.json)。

```sh
pnpm build

  --output .artifacts/continuation/new-run
```

命令默认运行八个插件和一个共享基线。`--agent <id>` 可选择任意一个插件，`--repeats` 可重复所选的完整一组。

统一设置：摘要输出上限 2,048、任务输出上限 4,096、每阶段最多 12 个模型步骤、`maxSummaryAttempts: 1`、不启用提供方传输重试。`keepRecentTokens` 通常为 256；Claude Code 和 Qwen Code 使用默认的全历史模式值 0。每次运行的实际配置均保存在报告中。工作负载为小型受控项目和强制手动压缩，未测试自动阈值或真正填满上下文。比较策略质量还需要更多重复次数和任务类型。协议见[评测说明](../../../docs/continuation-evaluation.zh-CN.md)。
