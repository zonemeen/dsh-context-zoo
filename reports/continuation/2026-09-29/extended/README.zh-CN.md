## 这次明确区分了什么

- **历史不足**：固定预算下 Claude Code、Codex、OpenCode，以及默认参数下 Cline，在第一处边界未达到 4,096-token 下限。它们继续完成任务，随后成功压缩两次。
- **默认保留策略未选出历史**：默认参数下 OpenCode 的后两处边界、Pi 的后两处边界没有可压缩历史；Pi 的第一处边界因历史不足跳过。任务仍完成，但摘要覆盖分别为一次和零次。
- **摘要截断与代码错误分别保留**：固定预算下 Qwen Code 的第三次摘要触及 4,096-token 上限，随后仍继续至阶段 10。最终六项验收失败，涉及重试次数含义、强制刷新与重试提示。其中重试错误在阶段 1、首次压缩之前已经出现，不能归因于压缩。
- **步骤预算耗尽**：固定预算下 ZCode 首阶段用完 12 次模型请求，尚未返回阶段完成响应，因此停止。最后一次开发测试已通过；重新检查保存的源文件也通过阶段 1 的 4/4 验收，但后九阶段没有执行，完整任务不能算通过。

每个模式只运行一次，源代码和历史由模型独立生成。表中差异不能证明某种预算或策略更好。默认参数仍受统一的 8,192-token 模型路由上限约束；这些运行使用手动边界，不评价默认自动触发策略。

694 次 HTTP 请求均返回 200，整个运行耗时 1,242.415 秒。所有请求均记录 API 用量；具体调用上限、阶段验收、耗时和重复读取见[完整报告](report.zh-CN.md)。
